# Adapters

Every implementation is an adapter: a module that maps an open standard, or a technology's native API when no
standard exists, onto a port. The adapters of this repository ship in one package, `@agent-layers/adapters`, one
subpath export per adapter: `@agent-layers/adapters/<name>`, with its source and README in
[`packages/adapters/src/<name>`](../packages/adapters/src). They are released together with the core; each adapter
folder can still have its own maintainer in CODEOWNERS. An adapter from another package loads through `plugins`.
How to write one: [guide.md](guide.md#write-an-adapter) and [CONTRIBUTING.md](../CONTRIBUTING.md).

## Maturity

| Level | Criteria |
|---|---|
| experimental | Descriptor and conformance test pass. Behaviour may change. |
| beta | Conformance passing in CI, a pinned upstream version (where there is an upstream) with a live contract test, an owner in CODEOWNERS. |
| stable | Beta for at least one minor release of its port without breaking changes, documented options, used in a reference setup. |

## Catalog

Direction: **outbound** consumes a standard or technology as a port; **inbound** exposes the stack through one.
Tiers: **prototype** adapters are for laptops, tests and demos; **production** adapters can run in production. The
readiness gate (`agent-layers check --profile <p>`) rejects prototype-only adapters on production-tier profiles.

Draft ports: `SecretPort`, `MemoryPort`, `IngestionPort` and `FeedbackPort` have a spec, a slot and a conformance suite
but no reference adapter yet; the slots `secrets`, `memory`, `ingestion` and `feedback` stay empty until one ships.

Technologies that speak a standard need no adapter of their own: Keycloak through `oidc`; Ollama, vLLM, LiteLLM and
hosted APIs through `openai-compatible`; Langfuse and Jaeger through `otlp`.
